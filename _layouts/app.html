--- layout: default css: app --- {%- comment -%} App landing page layout. Chains to default.html. IMPORTANT: this file's own `css: app` above only affects a page that has no `css:` of its own -- Jekyll does NOT cascade a layout's front matter down to the pages that use it. Every page on this layout must still set `css: app` itself (as cloud-storage-backup-drive.md does), or it renders with shell.css only and no pages/app.css. Confirmed the hard way: post.html originally relied on exactly this false cascade and pages/post.css silently never loaded. Fully front-matter-driven; the page body is empty (user, 29 Sep: no pasted guide text -- each app page is its own designed page). Required front matter (STATUS.md section 4): title, description, css (must be "app"), app_name, tagline, ios_url and/or android_url, category, features (icon, title, text), how_it_works (3x {title, text}), faqs (q, a). Optional, each adding a section: moments (+ moments_heading, moments_sub; 4x {icon, title, text}), compare ({heading, without[], with[], optional without_title / with_title}), tips (+ tips_heading; 3x {title, text}), guides (Daily Info slugs). Also steps_heading and trust_text (an app-specific privacy sentence -- only ever something confirmed about that particular app). Everything written for an app must stay inside what's confirmed about it (STATUS.md section 1): moments describe situations, tips and FAQs give general advice; neither may imply a feature the app isn't known to have.
